The shared instruction workflow

From authored instructions to your runtime.

Authored sources

Shared + platform + provider Reviewed files in your selected Git repository
aec render creates enrolled portable targets in the repository Review and commit the source and target changes aec codex apply (or aec copilot apply) deploys committed targets to an enrolled runtime Provider backup captures attributable runtime changes into sources and commits them Provider status compares runtime state with committed content

Selected local runtime

Codex or GitHub Copilot One explicitly enrolled platform and provider target

Rendering only changes files in the data repository. It does not change a runtime or create a Git commit. Ordinary AEC commands do not fetch or push.

Designed for control

Separate sources. Explicit operations.

Author for each scope

Put shared guidance, platform-specific policy, and provider-only instructions in separate sources. Explicitly enroll each target from reviewed, committed sources.

Preserve unrelated settings

Codex personality updates preserve other TOML entries. GitHub Copilot instruction management preserves unrelated configuration.

Migration has its own review

Existing 1.x data repositories use the explicit aec migrate 2.0 flow. Review the prepared changes and rehearse on a disposable copy before migrating.

Get started

Build on macOS ARM64.

You need Git, the .NET 10 SDK, and Xcode Command Line Tools. The installer places a self-contained Native AOT executable in your user directory and refreshes enrolled bundled AEC skills. It does not install the .NET runtime. 

git clone https://github.com/ferrywlto/ai-env-as-code.git
cd ai-env-as-code
./scripts/build-osx-arm64.sh
./scripts/install-osx-arm64.sh
aec version

Choose a data repository, initialize AEC, and review and commit the shared instructions, platform policy, and provider overlay before enrolling a target with aec codex init --repo /absolute/path/to/aec-data --enroll-shared. The setup guide explains the complete order.

For an existing 1.x repository, run aec migrate 2.0 --repo /absolute/path/to/aec-data only after reviewing the migration guide and rehearsing on a copy.
