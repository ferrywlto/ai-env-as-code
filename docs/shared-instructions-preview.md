# Composition review example

These illustrative inputs exercise the first increment; they are not a migration
of personal instructions or installable AEC managed blocks.

| Source | Selected text |
|---|---|
| Shared | Always propose a plan and ask for my decision before executing tasks. |
| macOS platform | Access only explicitly approved project roots and the selected harness home. |
| Codex overlay | Use the approved Codex model mapping when dispatching independent workers. |
| Copilot overlay | Empty until harness-specific preferences are verified. |

The caller supplies each provider's generated block. The function places it first,
then produces the following policy bodies (with two LF separators for these inputs).

## Codex policy body

```text
Always propose a plan and ask for my decision before executing tasks.

Access only explicitly approved project roots and the selected harness home.

Use the approved Codex model mapping when dispatching independent workers.
```

## Copilot policy body

```text
Always propose a plan and ask for my decision before executing tasks.

Access only explicitly approved project roots and the selected harness home.
```

The same approval and access policy reaches both targets. The caller must still
supply actual approved roots during integration; this example grants no new access.
Review focus: only the last, provider-specific section differs. Empty Copilot policy
adds no placeholder heading or directory. File creation is outside this function.
